## 2. Архитектуры развёртывания

* **Shared-nothing** — исследована статически и динамически (стенд allin1).
* **Shared-data** (CN + объектное хранилище, StarOS/StarManager) — исследована **только статически и частично**:
  BRPC LakeService, роли/привилегии STORAGE VOLUME. Динамически не проверялась: на стенде нет S3/MinIO.

## 3. Границы

### В границах
* FE (Java): аутентификация (`authentication/*`), авторизация (`authorization/*`, `sql/analyzer/Authorizer*`),
  MySQL-протокол и TLS (`mysql/*`), HTTP/REST (`http/*`), аудит (`plugin/AuditEvent`, `qe/AuditLogBuilder`,
  `qe/ConnectProcessor`, `common/util/LogUtil`), конфигурация (`common/Config.java`), служебные операторы
  (`qe/ExecuteScriptExecutor`).
* BE/CN (C++): BRPC-сервер, HTTP-сервер и его аутентификация, Arrow Flight, download/update_config, скриптовый
  движок `be/src/script`.
* Конфигурация по умолчанию (`Config.java`, `be/src/common/config.h`, `conf/*`).

### Вне границ / не исследовано (см. coverage.md)
* Ranger plugin — только точка обхода root (`RangerAccessController.hasPermission`).
* Коннекторы внешних каталогов (Hive/Iceberg/Hudi/Delta/JDBC/ES/Paimon) — авторизация внутри них не трассировалась.
* Полный по-методный анализ `FrontendServiceImpl` (91 Thrift-метод) и `PInternalService` (BRPC).
* StarOS/StarManager, fs_brokers, java-extensions (UDF runtime), format-sdk.
* Сторонние зависимости (SCA): `trivy.yaml` присутствует, но SCA-сканирование не запускалось.
* Kubernetes operator, Helm, процессы эксплуатации заказчика.

## 4. Окружение и ограничения
* Сборка FE/BE из исходников и unit-тесты **не запускались**: ограничение по времени. Для динамики использован
  официальный бинарный образ той же версии (`4.1.7-b81ff9c` совпадает с SHA).
* Лимит дескрипторов хоста 20000 < требуемых BE 60000: на стенде задан `min_file_descriptor_number = 10000`.
  На проверки безопасности это не влияет.
* Для проверки TLS на стенде включён тестовый keystore (самоподписанный, 30 дней). Это отклонение от
  конфигурации по умолчанию, оно отражено в test_plan.md.
* JDK на стенде: OpenJDK 17.0.20.1, `jdk.tls.disabledAlgorithms` включает `SSLv3, TLSv1, TLSv1.1, TLS_RSA_*`.
  Результаты TLS зависят от JDK заказчика.
* Нормативные документы /4/–/12/ **не приложены**. Требования, ссылающиеся на них (2.1, 2.3, 2.4-перечень
  алгоритмов, 3.1, 4.6, 4.7, 4.10, 5.6), оцениваются только в части, не зависящей от их содержания.
* Методологическое ограничение: находки описаны на уровне «механизм → код → риск → мера». Рабочие цепочки
  эксплуатации (исполнение произвольного кода, извлечение данных в обход SQL) не разрабатывались и не
  выполнялись. Там, где это существенно, вывод основан на исходном коде и проверке предусловий (привилегии,
  значения конфигурации), а не на демонстрации эксплуатации.
